# ADR-011 — Локальный Nemotron как координатор Orca

Статус: **Отозвано пользователем 2026-10-26; решение сохранено только как
история эксперимента. Nemotron не используется в дальнейшей работе проекта.**
Исходное решение датировано 2026-10-24.
Связанные требования / TASK: WF-COORD-001…WF-COORD-006; TASK-WF-01.

## Контекст

Координатор OpenCode ведёт очередь Orca, подготавливает TASK и чек-листы,
обрабатывает сообщения и обновляет состояние. Его длительный контекст создаёт
существенный расход облачных токенов. На хосте установлен локальный NVIDIA
Nemotron 3.5 Bolt E4B Q4_K_M, доступный OpenCode как
`local-nemotron/nemotron-bolt` через `http://127.0.0.1:18080/v1`.

Модель проверена на русском ответе, нативном вызове инструмента и соблюдении
блокировки `WAITING_REVIEW`. Установка использует контекст 32768 токенов и один
одновременный запрос. Она работает на RTX 3070 Ti с 8 ГиБ VRAM. Контрольная
проверка не затрагивала задачи Orca или проектные файлы.

Текущий TASK-MVP-03 уже реализован и ожидает зарезервированное независимое R2
ревью Codex. Его исполнитель, ревьюер, чек-лист, бюджет и диспетч не меняются.

## Альтернативы

| Вариант | Преимущества | Издержки и ограничения |
| --- | --- | --- |
| Nemotron — только координатор; исполнители и ревьюеры остаются на текущих маршрутах | Снижает облачный расход длительной сессии координатора; сохраняет независимость исполнителя и ревьюера | Качество координации ограничено локальной моделью и контекстом 32K; нужна проверка вызовов Orca-инструментов |
| Перевести на Nemotron также исполнителя и ревьюера | Меньше облачного расхода для всех ролей | Одна модель выполняла бы независимую проверку; качество исполнения и ревью не подтверждено |
| Оставить облачного координатора | Не требует изменения запуска | Сохраняет расход облачных токенов координатора |

## Решение и последствия

1. После завершения текущего R2 ревью TASK-MVP-03 и безопасной передачи Run
   локальный `local-nemotron/nemotron-bolt` используется только в роли
   координатора OpenCode в этом репозитории.
2. Новая координационная сессия запускается через Orca с явным выбором модели.
   До начала работы подтверждаются фактическая модель в квитанции запуска,
   рабочая копия и привязка к существующему Run. Параллельных координаторов не
   оставлять.
3. Реализация остаётся за отдельным OpenCode-исполнителем по действующему
   маршруту `deepseek-v4.1-flash-free`; R1-ревью остаётся за независимым
   OpenCode `minimax-m3.1-flash-free`, R2/R3 — за Codex согласно
   `routing-and-budget.md`.
4. Не менять пользовательскую модель OpenCode по умолчанию и не запускать
   локальную модель для других проектов или ролей этим решением.
5. Если сервер Nemotron не готов, модель не подтверждена или вызов инструмента
   не работает, новую координационную цепочку остановить как BLOCKED. Не делать
   незаметный переход к облачной модели; возобновление использует отдельное
   решение пользователя.
6. Внедрение оформляется отдельной `TASK-WF-01` после PASS TASK-MVP-03. Она
   относится к операционному workflow, не входит в число семи продуктовых TASK
   MVP + Batch и не меняет продуктовый API или данные.

Проверка соблюдения: фактическая модель в launch receipt равна
`local-nemotron/nemotron-bolt`; локальный координатор привязан к ожидаемому Run,
успешно читает фактический статус через Orca-инструмент и не расходует
облачные токены; текущая модель по умолчанию, исполнитель и reviewer остаются
на прежних настройках; автоматический fallback отсутствует.

Основание утверждения: сообщение пользователя от 2026-10-24 в текущей сессии:
«Подтверждаю» в ответ на план локального Nemotron только для координатора,
сохранения остальных ролей и текущего R2 review без изменений.

## Поправка от 2026-10-26

Попытка выполнить пункт 2 через `orca agent launch` с явной моделью
`local-nemotron/nemotron-bolt` дважды вернула `capability_unsupported`
(«The execution host cannot verify this OpenCode model launch»), в том числе
при здоровом локальном сервере (`/health` = `ok`, `/v1/models` = `nemotron-bolt`,
ctx 32768). Launch receipt с фактической моделью получить нельзя.

Пользователь отдельно разрешил альтернативный запуск. Допустимый способ:
Orca `terminal create` с командой `OpenCode-Bolt.ps1` (или эквивалентной),
которая явно задаёт `--model local-nemotron/nemotron-bolt` и локальный
OpenCode-конфиг. Фактическая модель подтверждается совокупностью:

1. terminal create receipt: handle, worktree и точная команда с `--model`;
2. метаданные OpenCode-сессии: `model = local-nemotron/nemotron-bolt`,
   cost 0, отсутствие облачного provider;
3. лог/процесс локального `llama-server`, обслуживший запросы сессии;
4. привязка сессии к `run_68046cea3eb4` с generation больше предыдущей.

Остальные требования ADR-011 не меняются: локальная модель только
координатор, параллельных координаторов нет, глобальная модель OpenCode и
другие проекты не меняются, продуктовый код/данные не затрагиваются, при
неподтверждённой модели/инструменте — BLOCKED, облачный fallback запрещён.
Независимый R1-ревьюер проверяет перечисленные артефакты вместо launch
receipt. Основание: ответ пользователя «Разрешить альтернативный запуск
(Recommended)» 2026-10-26.

## Поправка от 2026-10-26 — ограниченный Codex-маршрут

По явному сообщению пользователя на текущий день локальный
`local-nemotron/nemotron-bolt` остаётся единственным координатором; облачный
OpenCode отключён. Отдельные Codex-агенты могут реализовать и независимо
ревьюировать задачи. Для WF-01 это заменяет только маршруты исполнителя и
R1-ревьюера в AC-005/009; все AC ID и функциональные требования сохраняются.
Операционный scope также включает изменения выделенного внешнего локального
профиля, launcher и диагностик.

Исключение действует до 2026-10-27 00:00 Europe/Moscow. Luna medium применяется
к текущей настройке; Sol medium — к независимому WF-01 review и MVP-04
implementation по существующему design; Astra high — к независимому R2 review
MVP-04. После WF-01 acceptance ранее утверждённую очередь MVP разрешено
продолжать через Codex без повторного подтверждения старта. Глобальные модели,
аккаунт и тариф не меняются; сброс/покупка кредитов и пересчёт API cost в
подписочный лимит запрещены. Фактическое исчерпание провайдера блокирует
зависимую цепочку и требует нового решения даже после reset. Координатор только
локальный Nemotron, параллельные координаторы запрещены.

Основание: сообщения пользователя Codex/Nemotron и последующее дополнение о
выборе GPT по задаче от 2026-10-26; ревизии указаны в APPROVALS и evidence
`TASK-WF-01-C2.md`.

## Отзыв решения от 2026-10-26

Пользователь отозвал решение использовать Nemotron в связке: «Nemotron убираем
из связки. Работа с ним не понравилась вестись не будет». Поэтому ADR-011
больше не задаёт рабочую конфигурацию, локальная модель и профили запуска не
используются в проекте, TASK-WF-01 прекращён без продолжения. Codex остаётся
координатором Orca; модели для остальных ролей выбираются по
`docs/workflow/MODEL-ROUTING.md`. Продуктовая архитектура и объём MVP не
изменены. Все первоначальные требования, неудачные попытки и BLOCKED/FAIL
результаты оставлены ниже/в связанных evidence как неизменённая история.

## Актуальное исключение CODEX_COORD_20261026

Новое явное решение пользователя 2026-10-26 передаёт очередь Codex-координатору;
Nemotron больше не управляет очередью. MVP-04 разрешён при BLOCKED WF-01.
Этот раздел имеет приоритет над предыдущими ролевыми ограничениями и требованием
WF-01 PASS перед продуктовым dispatch. Codex ведёт workflow/ожидание; отдельный
gpt-6.1-sol medium реализует MVP-04 по готовому design, независимый
gpt-6-astra high проводит R2 review. Полный маршрут и точная цитата:
docs/workflow/MODEL-ROUTING.md и docs/workflow/APPROVALS.md.
AC, allowlist, архитектура, срок сегодняшнего исключения и весь расход сохранены.
WF-01 BLOCKED/NOT_ACCEPTED, 3/4 calls, 1/2 reviews; его исправление не запускается.
Commit только после routed PASS. Push/merge/deploy/reset/account changes запрещены.
