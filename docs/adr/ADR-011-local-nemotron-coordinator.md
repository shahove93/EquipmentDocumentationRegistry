# ADR-011 — Локальный Nemotron как координатор Orca

Статус: Принято. Дата: 2026-10-24.
Связанные требования / TASK: WF-COORD-001…WF-COORD-006; TASK-WF-01.

## Контекст

Координатор OpenCode ведёт очередь Orca, подготавливает TASK и чек-листы,
обрабатывает сообщения и обновляет состояние. Его длительный контекст создаёт
существенный расход облачных токенов. На хосте установлен локальный NVIDIA
Nemotron 3.5 Bolt E4B Q4_K_M, доступный OpenCode как
`local-nemotron/nemotron-bolt` через `http://127.0.0.1:18080/v1`.

Модель проверена на русском ответе, нативном вызове инструмента и соблюдении
блокировки `WAITING_REVIEW`. Установка использует контекст 32768 токенов и один
одновременный запрос. Она работает на RTX 3070 Ti с 8 ГиБ VRAM. Контрольная
проверка не затрагивала задачи Orca или проектные файлы.

Текущий TASK-MVP-03 уже реализован и ожидает зарезервированное независимое R2
ревью Codex. Его исполнитель, ревьюер, чек-лист, бюджет и диспетч не меняются.

## Альтернативы

| Вариант | Преимущества | Издержки и ограничения |
| --- | --- | --- |
| Nemotron — только координатор; исполнители и ревьюеры остаются на текущих маршрутах | Снижает облачный расход длительной сессии координатора; сохраняет независимость исполнителя и ревьюера | Качество координации ограничено локальной моделью и контекстом 32K; нужна проверка вызовов Orca-инструментов |
| Перевести на Nemotron также исполнителя и ревьюера | Меньше облачного расхода для всех ролей | Одна модель выполняла бы независимую проверку; качество исполнения и ревью не подтверждено |
| Оставить облачного координатора | Не требует изменения запуска | Сохраняет расход облачных токенов координатора |

## Решение и последствия

1. После завершения текущего R2 ревью TASK-MVP-03 и безопасной передачи Run
   локальный `local-nemotron/nemotron-bolt` используется только в роли
   координатора OpenCode в этом репозитории.
2. Новая координационная сессия запускается через Orca с явным выбором модели.
   До начала работы подтверждаются фактическая модель в квитанции запуска,
   рабочая копия и привязка к существующему Run. Параллельных координаторов не
   оставлять.
3. Реализация остаётся за отдельным OpenCode-исполнителем по действующему
   маршруту `deepseek-v4.1-flash-free`; R1-ревью остаётся за независимым
   OpenCode `minimax-m3.1-flash-free`, R2/R3 — за Codex согласно
   `routing-and-budget.md`.
4. Не менять пользовательскую модель OpenCode по умолчанию и не запускать
   локальную модель для других проектов или ролей этим решением.
5. Если сервер Nemotron не готов, модель не подтверждена или вызов инструмента
   не работает, новую координационную цепочку остановить как BLOCKED. Не делать
   незаметный переход к облачной модели; возобновление использует отдельное
   решение пользователя.
6. Внедрение оформляется отдельной `TASK-WF-01` после PASS TASK-MVP-03. Она
   относится к операционному workflow, не входит в число семи продуктовых TASK
   MVP + Batch и не меняет продуктовый API или данные.

Проверка соблюдения: фактическая модель в launch receipt равна
`local-nemotron/nemotron-bolt`; локальный координатор привязан к ожидаемому Run,
успешно читает фактический статус через Orca-инструмент и не расходует
облачные токены; текущая модель по умолчанию, исполнитель и reviewer остаются
на прежних настройках; автоматический fallback отсутствует.

Основание утверждения: сообщение пользователя от 2026-10-24 в текущей сессии:
«Подтверждаю» в ответ на план локального Nemotron только для координатора,
сохранения остальных ролей и текущего R2 review без изменений.
