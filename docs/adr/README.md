# Архитектурные решения проекта (ADR)

Индекс решений, принятых в Equipment Documentation Registry.

Этот каталог — **единственное постоянное место**, где фиксируются архитектурные
решения проекта. Он создан для того, чтобы новая сессия работы могла восстановить
контекст, не обращаясь к переписке.

## Как читать

- Решение считается действующим, если его статус `Принято`.
- Любой код, который меняет поведение, описанное в ADR, должен ссылаться на
  соответствующий документ — так уже сделано в `app/api/products/schemas.py`,
  `app/api/variants/schemas.py`, `app/services/variant_service.py`,
  `app/services/document_type_service.py` и миграции `9e6a954d41be`.
- Решение, помеченное как `Черновик`, не подтверждено кодом и не должно
  использоваться как основание для реализации.

## Исторические номера

Номера **ADR-001…ADR-004 считаются историческими**: они предшествуют ADR-005…008
в последовательности проекта, но **их существование не подтверждено документально** —
в репозитории нет ни самих документов, ни ссылок на них (проверено по `app/`,
`tests/`, `alembic/`, `README.md`).

Следствия:

- содержание этих решений **неизвестно** и здесь не реконструируется;
- **не переиспользуйте эти номера** и **не перенумеровывайте** ADR-005…ADR-008;
- **ADR-009 не присвоен и не зарезервирован.** Выдача номера требует отдельного
  согласования; в частности, она не выполнена для
  [связи сертификатов с типоразмерами](DOCUMENT-VARIANT-RELATIONSHIP.md), которая
  остаётся черновиком без номера.

Номер **ADR-008 присвоен** 2026-10-13 решению
[о жизненном цикле проверки документа](ADR-008-document-verification-lifecycle.md).
