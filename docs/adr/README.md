# Архитектурные решения проекта (ADR)

Индекс решений, принятых в Equipment Documentation Registry.

Этот каталог — **единственное постоянное место**, где фиксируются архитектурные
решения проекта. Он создан для того, чтобы новая сессия работы могла восстановить
контекст, не обращаясь к переписке.

## Как читать

- Решение считается действующим, если его статус `Принято`.
- Любой код, который меняет поведение, описанное в ADR, должен ссылаться на
  соответствующий документ — так уже сделано в `app/api/products/schemas.py`,
  `app/api/variants/schemas.py`, `app/services/variant_service.py`,
  `app/services/document_type_service.py` и миграции `9e6a954d41be`.
- Решение, помеченное как `Черновик`, не подтверждено кодом и не должно
  использоваться как основание для реализации.

## Исторические номера

Номера **ADR-001…ADR-004 считаются историческими**: они предшествуют ADR-005…008
в последовательности проекта, но **их существование не подтверждено документально** —
в репозитории нет ни самих документов, ни ссылок на них (проверено по `app/`,
`tests/`, `alembic/`, `README.md`).

Следствия:

- содержание этих решений **неизвестно** и здесь не реконструируется;
- **не переиспользуйте эти номера** и **не перенумеровывайте** ADR-005…ADR-010;
- **ADR-010 присвоен 2026-10-19** решению
  [о привязке документов к типоразмерам и материальном поиске](ADR-010-document-variant-links-and-search.md).
  Прежний черновик
  [«Связь сертификатов с типоразмерами»](DOCUMENT-VARIANT-RELATIONSHIP.md)
  поглощён этим решением и сохраняется как историческая справка.

Номера **ADR-008** и **ADR-009** присвоены 2026-10-13 решениям
[о жизненном цикле проверки документа](ADR-008-document-verification-lifecycle.md)
и [об архитектуре вложений](ADR-009-document-attachments.md). Второе решение
уточняет первое и **не отменяет ни одного его правила**.

## Решения, принятые, но не выполненные до конца

Статус `Принято` означает, что решение обязательно к исполнению, а не что код
написан. У [ADR-009](ADR-009-document-attachments.md) **сервисный и HTTP-слой
реализованы**: общий механизм `record_reopened()`, три кода причины,
`FileService.attach()` / `detach()`, общий модуль
`app/services/transaction.py`, охранник `TransactionAlreadyOpenError`,
блокировки `Document` → `File`, автоматический возврат в `pending`,
компенсация добавления, удаление файла только после подтверждённого `commit`,
журналирование через `logging`, доменная ошибка `AttachmentNotFoundError`,
пять файловых маршрутов, DI `get_file_service` / `get_storage`,
`FileOut` / `FileListOut`, потоковая загрузка и скачивание,
`ClosingStreamingResponse`, `python-multipart==0.0.32`, постоянный JSON
Lines-журнал (TASK-MVP-01) и **report-only сверка осиротевших файлов**
(TASK-MVP-02): `LocalStorageBackend.iter_files()`,
`app/services/storage_reconciliation.py` и CLI `python -m app.reconcile_storage`
без удаления, DML и расписания. **Сверка SHA-256 при скачивании и индекс
`ix_files_document_id_id` реализованы** (TASK-MVP-03): проверенная копия blob
отдаётся только после сравнения с `File.sha256`, миграция `e4b8c2d16a70`
создаёт non-unique btree `(document_id, id)`.

У [ADR-008](ADR-008-document-verification-lifecycle.md) **сервисный и HTTP-слой
также реализованы**: шесть документных операций (`POST` / `GET` коллекции,
`GET` / `PATCH` карточки, `POST .../verification`, `GET .../verification-history`)
и read-метод `DocumentService.history()`; подтверждение и отклонение достижимы
через HTTP.

У [ADR-010](ADR-010-document-variant-links-and-search.md) **сервисный и
HTTP-слой также реализованы**: `DocumentVariantService` (`list_variants` /
`set_variants`), два маршрута привязки (`GET` / `PUT
/documents/{id}/variants`) и материальные фильтры `GET /documents`. Открытые
пункты самого решения — отдельное событие истории для изменений привязок,
индексы под `LIKE '%…%'`, привязка к `Product` / `Batch` и семантика каскадного
удаления `ProductVariant`.

**Не реализовано то, что осталось:** аутентификация и авторизация. Постоянный
журнал (TASK-MVP-01), **report-only** сверка осиротевших файлов (TASK-MVP-02),
сверка SHA-256 при скачивании и индекс `ix_files_document_id_id` (TASK-MVP-03)
реализованы; удаление кандидатов и автоматическое расписание в объём сверки
не входят. Таблицы «Статус реализации» в обоих ADR перечисляют всё построчно.
