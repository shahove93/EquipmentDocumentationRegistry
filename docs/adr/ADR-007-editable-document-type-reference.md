# ADR-007. Редактируемый справочник типов документов

| | |
| --- | --- |
| **Номер** | ADR-007 |
| **Статус** | ✅ Принято |
| **Дата принятия** | не зафиксирована в репозитории |
| **Затрагивает** | `DocumentType`, `document_types` |
| **Миграция** | `6a736cbf733b` — `create document_types` |
| **Ссылки в коде** | `app/api/document_types/router.py`, `app/api/document_types/schemas.py`, `app/services/document_type_service.py` |

## Контекст

Виды документов, которые хранит система («Паспорт», «Декларация о соответствии»,
«Сертификат соответствия», «Протокол испытаний»), задаются конкретной
организацией и зависят от её номенклатуры дел. Жёстко зашитый в код или
предзаполненный миграцией набор типов быстро перестаёт соответствовать реальности
и требует изменения кода или миграции для каждой правки.

Кроме того, справочник должен оставаться целостным: одинаковые названия,
различающиеся регистром или пробелами, приводят к дубликатам и ошибкам при
привязке документов.

## Принятое решение

1. **`DocumentType` — пользовательский редактируемый справочник.** Типы
   документов вводятся через API, а не поставляются при развёртывании.
2. **Пользователь может создавать и переименовывать виды документов.**
   Переименование — штатная операция, выполняемая через `PATCH`.
3. **Ограничение `UNIQUE(name)` действует в базе данных.**
   Имя ограничения: `document_types_name_key`. Длина столбца —
   `VARCHAR(100) NOT NULL`.
4. **Создание дубликата возвращает HTTP 409.** Проверка выполняется не в
   схеме, а сервисом поверх ошибки целостности, поэтому дубликат доходит до
   базы и порождает настоящий конфликт, а не отсекается валидатором.
5. **Удаление пока не реализовано.** В приложении отсутствуют маршруты `DELETE`
   (всего 21 маршрут, ни одного `DELETE` и ни одного `PUT`). Справочник можно
   наполнять и переименовывать, но не удалять — это осознанное промежуточное
   состояние: удаление требует продумать поведение `documents.document_type_id`,
   который объявлен `NOT NULL` и не имеет `ON DELETE` действия.
6. **Список поддерживает `limit` / `offset`.** Значения по умолчанию:
   `limit=50`, `offset=0`; допустимый диапазон `limit` — от 1 до 100,
   `offset` — от 0.
7. **Стартовый набор типов документов пока не внесён в рабочую базу.** В таблице
   `public.document_types` нет ни одной записи; наполнение выполняет
   пользователь через `POST /document-types`.

### О реализации пункта 4

`DocumentTypeService._commit()` перехватывает `IntegrityError`, откатывает
транзакцию и сверяет **и** SQLSTATE `23505`, **и** имя ограничения
`document_types_name_key`. Нарушение любого другого ограничения не
преобразуется в доменную ошибку, а всплывает как собственная ошибка базы данных.
То же сравнение выполняется при `PATCH`.

## Последствия

**Положительные**

- Добавление нового вида документа не требует ни изменения кода, ни миграции.
- Ограничение уникальности на уровне базы исключает дубликаты даже при гонке
  параллельных запросов.
- Сравнение происходит после удаления внешних пробелов, поэтому
  `"  Паспорт  "` конфликтует с сохранённым `"Паспорт"`.

**Отрицательные**

- **Пустой справочник на старте.** Пока пользователь не введёт хотя бы один тип,
  создать документ невозможно: `documents.document_type_id` обязателен, а API
  документов ещё не реализован.
- **Невозможно убрать ошибочно созданный тип** — только переименовать.
- Регистр учитывается: `Паспорт` и `ПАСПОРТ` — два разных типа
  (`tests/test_document_type_schemas.py::test_case_is_not_changed` фиксирует это
  как документированное текущее поведение).

## Ограничения

- Решение **не утверждает**, что первоначальное наполнение справочника
  реализовано: в рабочей базе таблица пуста.
- Переименование меняет только `name`; идентификатор `id` не меняется.
- Сравнение имён регистрозависимо — нормализация регистра сознательно не
  выполняется, поскольку типы документов вводятся человеком, а приведение
  «Паспорт» к «ПАСПОРТ» изменило бы отображаемое пользователем значение.
- Удаление не реализовано; добавление `DELETE` потребует нового решения о
  поведении при наличии связанных документов.
- `document_types` не защищены от `CASCADE`-удаления: связь в `documents`
  объявлена без `ON DELETE`, то есть удаление типа при наличии документов
  приведёт к ошибке внешнего ключа.
