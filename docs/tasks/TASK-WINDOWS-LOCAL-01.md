# TASK-WINDOWS-LOCAL-01 — Устанавливаемый локальный режим Windows

Статус: PASS — C1 и независимое дополнение G01/G02, 2026-10-27
Основание: [ADR-012](../adr/ADR-012-windows-local-installation.md)
Базовый revision: `1c362598e67f9a7645de2416e79c2bb8ca3f3dc4`

## Цель

Подготовить устанавливаемую Windows x64 поставку EDR для одного компьютера,
включающую локальный API, frontend и PostgreSQL. После установки пользователь
открывает интерфейс ярлыком; данные и вложения сохраняются локально.

## Исполнение

- Риск: R2 — дистрибуция пересекает frontend/backend, локальную БД и операции
  над пользовательскими файлами.
- Подход A1/C1: единая устанавливаемая Windows x64 поставка по ADR-012.
- Приёмка: независимый Codex review по критериям ниже. Исторический полный C1
  завершился BLOCKED из-за отсутствующих ресурсов; его [отчёт](../workflow/reviews/TASK-WINDOWS-LOCAL-01-C1.md)
  сохранён без изменения первоначального вердикта.
- После включения Sandbox и reboot выполнены недостающие чистые и интерактивные
  проверки. Независимый Astra/high [подтвердил G01/G02 PASS](../workflow/reviews/TASK-WINDOWS-LOCAL-01-C1-supplement.md);
  совместно с C1 это закрывает неизменные критерии 1–8. [Evidence](../workflow/evidence/TASK-WINDOWS-LOCAL-01-clean-windows.md).
  Полное review1/2, failed0, подход A1/C1 сохранены; дополнение — отдельная
  ограниченная экспертиза без новой кодовой подачи или полного review.
- Лимиты расхода на TASK не вводятся. Фактические расходы Codex учитываются;
  остановка — только при отказе провайдера или прямом решении пользователя.
- Существующие незакоммиченные изменения GitHub presentation и workflow вне
  этого TASK сохраняются и не включаются в его diff.

## Объём

- проверить варианты упаковки FastAPI, frontend build, PostgreSQL и управления
  жизненным циклом приложения на Windows;
- реализовать установку/первый запуск, локальное открытие интерфейса и остановку;
- хранить базу и вложения вне каталога установки;
- обеспечить миграцию схемы при обновлении с безопасным поведением при ошибке;
- реализовать согласованные backup/restore БД и файлов;
- сохранить данные при обновлении и стандартном удалении приложения;
- проверить наличие требуемого Microsoft Visual C++ x64 Runtime; если он
  отсутствует — сообщить пользователю и открыть официальную страницу Microsoft,
  не включая runtime DLL/package в EDR-поставку;
- подготовить краткую русскую инструкцию установки, эксплуатации и восстановления.

## Вне объёма

- сетевой доступ, многопользовательский режим, аутентификация и роли;
- облачное размещение, удалённое управление и автообновления через интернет;
- переписывание React-интерфейса в нативный desktop UI;
- изменение доменной модели, API-семантики и пользовательских сценариев MVP;
- перенос существующих данных из WSL в Windows.

## Критерии приёмки

1. Установка на чистой поддерживаемой Windows x64 машине не требует WSL, Docker,
   Node.js или ручной установки Python/PostgreSQL.
2. Запуск из ярлыка открывает локальный интерфейс; API не слушает LAN-интерфейсы.
3. Основной сценарий работает: создать запись, прикрепить файл, перезапустить
   приложение, открыть запись и скачать тот же файл.
4. Backup содержит БД и вложения; restore в пустой data directory восстанавливает
   запись и файл как согласованную пару.
5. Неуспешная миграция не удаляет и не перезаписывает исходные данные.
6. Обновление и обычное удаление сохраняют пользовательский data directory.
7. Точечные backend/frontend checks и clean-install smoke-check имеют записанные
   результаты; неподтверждённые Windows-платформой проверки явно помечены.
8. При отсутствующем Visual C++ runtime продукт явно сообщает prerequisite и
   открывает официальную страницу Microsoft; EDR installer не содержит CRT.

## Предположения и ресурсы

- Первая поддерживаемая платформа: Windows 10/11 x64.
- Целевая установка и запуск должны быть проверены на Windows; WSL проверка не
  заменяет этот smoke-check.
- Технология упаковки и версии включаемых runtime фиксируются после короткого
  технического прототипа и проверки лицензий/процедуры обновления.
- Не использовать реальные клиентские документы в тестировании.

## Проверки

- текущий backend suite после изменений backend;
- frontend typecheck/build после изменений frontend;
- миграционный smoke-check на отдельной тестовой БД;
- чистая Windows x64 установка, запуск, перезапуск, backup/restore и uninstall
  с проверкой сохранности данных.
